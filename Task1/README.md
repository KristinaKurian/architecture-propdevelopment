# Задание 1. Разработка проверочного листа по безопасности данных

Цель задания — классифицировать данные, которые обрабатывает PropDevelopment, определить основные риски для каждой категории данных и оценить их критичность.

В рамках анализа данные распределены по четырём категориям:

- публичные данные;
- внутренние данные;
- конфиденциальные данные;
- секретные данные.

Для каждой категории рассмотрены следующие риски:

- утечка данных;
- потеря данных;
- искажение данных;
- некачественные данные;
- обесценивание данных.

Для оценки рисков используется шкала:

- **Незначительный** — влияние на бизнес и пользователей ограничено;
- **Значительный** — риск может привести к заметным операционным, финансовым или репутационным последствиям;
- **Критический** — риск может привести к серьёзному нарушению бизнес-процессов, компрометации чувствительных данных, финансовым или юридическим последствиям.

## Решение

| Категория данных | Примеры данных | Основные риски и оценка |
|---|---|---|
| **Публичные данные** | Каталог недвижимости, цены, фотографии, характеристики квартир, информация о ЖК, публичные акции | Утечка — **незначительный**; потеря — **значительный**; искажение — **значительный**; некачественные данные — **значительный**; обесценивание — **значительный** |
| **Внутренние данные** | Данные проведения онлайн-туров, данные менеджеров продаж, API-контракты, процессы проведения, внутренние отчёты, обезличенный мониторинг | Утечка — **значительный**; потеря — **значительный**; искажение — **значительный**; некачественные данные — **значительный**; обесценивание — **значительный** |
| **Конфиденциальные данные** | Ф. И. О., телефон, email, данные CRM, данные собственников, бронирования, результаты осмотров, данные онлайн-сделок, документы клиентов, данные ЖКУ, история платежей, данные партнёров | Утечка — **критический**; потеря — **критический**; искажение — **критический**; некачественные данные — **критический**; обесценивание — **значительный** |
| **Секретные данные** | Пароли и учётные данные, API keys, access/service tokens, ключи шифрования, приватные ключи и сертификаты, credentials государственных систем и партнёров, административные учётные данные, информация о критических уязвимостях | Утечка — **критический**; потеря — **критический**; искажение — **критический**; некачественные данные — **критический**; обесценивание — **значительный** |

## Обоснование оценки рисков

### Публичные данные

Основной риск связан не с раскрытием информации, так как эти данные изначально предназначены для публикации, а с их доступностью, целостностью и актуальностью. Массовая потеря каталога может нарушить работу витрины и процесс продаж. Ошибочные или устаревшие цены и характеристики объектов могут привести к жалобам клиентов, финансовым и репутационным потерям.

### Внутренние данные

Утечка внутренних данных может раскрыть особенности процессов и интеграций компании. Потеря или искажение информации затруднит работу продуктовых и операционных команд. Некачественные или устаревшие внутренние данные могут приводить к ошибочным решениям и перестают отражать реальное состояние процессов.

### Конфиденциальные данные

Эта категория содержит персональные, финансовые и имущественные данные клиентов и собственников. Их утечка или искажение может привести к нарушениям законодательства, финансовым потерям и серьёзному репутационному ущербу. Риск некачественных данных также оценивается как критический, поскольку в текущей системе уже наблюдаются случаи, когда одному клиенту отображаются данные другого клиента.

### Секретные данные

Компрометация паролей, токенов, API-ключей, сертификатов и других учётных данных может предоставить несанкционированный доступ к системам и данным компании. Потеря или подмена ключей и credentials способна нарушить работу интеграций и механизмов защиты. Устаревшие сертификаты и credentials создают риск отказов и компрометации систем.
